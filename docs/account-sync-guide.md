# 账号同步使用指南

适用于 DeepStudy 1.2.51 的 Windows、Mac 和 Android 客户端。

完成账号连接后，日常保存修改会自动同步，不需要每次点击“立即同步”。本机保存和上传云端是两个步骤：离线也能继续使用；换设备前，确认当前设备已经同步，再在另一台设备打开应用。

## 第一次连接每台设备

所有设备使用同一个账号，并保留相同的同步服务地址。不同账号或不同服务的数据各自独立。

| 设备情况 | 操作 |
| --- | --- |
| Windows 或 Mac 第一次连接 | 打开“账号同步”，登录，点击“预览首次同步”，核对本机与账号数据，再点击“确认并同步”。每台设备只需完成一次。 |
| 没有旧数据的新 Android 设备 | 在“我的”中登录，应用自动连接并下载账号数据，不需要确认空白导入。 |
| Android 登录前已有本机数据 | 在“我的”中预览首次同步，再选择合并本机旧数据；也可以选择“不上传本机旧数据，仅同步账号”。 |
| 已连接过的设备重新打开应用 | 保留登录状态且首次设置已完成时，自动恢复日常同步。 |

首次预览用于查看影响。确认后才会执行合并和写回；确认前后数据发生变化时，应用可能要求重新预览。首次同步期间保持应用打开。注册时显示的恢复码应离线保存，它用于账号恢复。

## 日常如何在电脑与手机之间切换

例如，上午在 Windows 保存任务 A，下午在 Mac 新增任务 B，晚上在 Android 查看：只要各端登录同一账号、已连接同步并且能够联网，A 和 B 会自动汇入同一账号，无需来回导出文件。

Windows 和 Mac 保存修改后，会短暂等待连续编辑结束再上传；空闲时约每分钟检查其他设备的更新，刚发生同步活动时检查更频繁。Android 保存后自动上传，在前台约每分钟检查更新。回到应用或恢复联网时，两端都会主动检查。

切换设备时可以按下面的顺序操作：

1. 在当前设备保存修改。
2. 查看“账号同步”或“我的”：确认没有待上传项目，也没有需要处理的错误或冲突。
3. 在另一台设备打开应用，等待自动同步完成后继续编辑。需要立即检查时，可点“立即同步”。

“自动同步”需要客户端有运行机会。电脑应用退出、电脑休眠、手机应用被系统关闭或长期留在后台时，不能保证继续传输。手机回到前台后会继续检查。刚保存就立即关闭设备，不能视为已经上传。

## 哪些情况需要自己选择

### 长期任务备注

长期任务中的标题、备注和提醒也会自动保存并同步。输入后等待“已自动保存”，再确认账号同步没有待上传项目。新版电脑客户端即使一直打开任务详情，也会显示收到的新备注；仅点击文字或移开光标不会把旧内容重新上传。正在输入的内容会保留，连续切换任务也会分别保存各条任务的修改。

如果每日任务已更新，某条长期任务仍显示旧内容，请先确认 Windows 和 Mac 都已更新至 1.2.51 或更高版本，再返回任务列表并重新打开该任务。仍不一致时查看账号同步中的冲突提示，保留两端内容后再比较处理。

### 多端同时编辑

修改不同记录时会自动合并。两台设备同时修改同一条记录，而且彼此还没拿到对方的新版本时，可能发生冲突。例如，两端同时修改同一个长期任务，即使改的是不同字段，也不能假定会自动按字段合并。

出现冲突后，应用保留供比较的本机与云端版本，不会因为显示冲突就丢弃本机修改。在电脑的“查看冲突”或 Android 的冲突列表中比较内容，然后明确选择保留哪一版。

选择“保留云端”意味着放弃该记录尚未上传的本机版本；选择“保留本机”会按确认的云端版本重新提交本机内容。冲突处理期间另一端又有变化时，可能需要再次比较。这里的选择只针对相应记录，不是用整台设备覆盖整个账号。

## 离线和同步过程中继续编辑

离线保存的内容先保存在本机，待上传队列会保留，恢复联网后继续处理。网络响应丢失时，客户端使用已保存的操作标识重试，收到确认后才结算对应的上传。

正常日常同步进行中，仍可保存新修改。客户端会保留同步期间的新版本，继续安排上传；旧响应不会直接把这些已保存修改覆盖掉。这个保护针对已经保存的内容，尚未保存的输入不属于同步队列。

不要通过清空应用数据、卸载应用或删除本机数据来“修复同步”；这些操作可能移除唯一尚未上传的副本。退出账号不等于删除本机数据；重新登录原账号后，查看该账号的待上传状态。

## 如何看懂状态

| 状态或提示 | 含义与操作 |
| --- | --- |
| 已同步 / 最近已同步时间 | 最近一轮同步已完成。还要确认待上传和冲突数量为零。 |
| 待上传 | 修改已保存在本机，还没有全部获得云端确认；保持联网和应用运行。 |
| 正在同步 | 正在传输或核对，数据较多时需要更久。 |
| 离线 | 可继续编辑，恢复联网后自动补传。 |
| 今日读取 / 写入额度已用完 | 同步服务的每日额度暂时不足，本机修改仍保留。按提示等待自动重试，不需要重复点击。 |
| 云端存储空间不足 | 需要服务管理员处理云端空间；本机内容仍保留，处理后再同步。 |
| 登录已失效 | 重新登录同一账号；这不代表待上传数据已删除。 |
| 冲突 / 需要比较 | 比较本机和云端版本，明确选择保留内容。 |

待上传数量包含内部同步记录，不一定等于界面中可见的任务数量；图片分片等内容也可能占多条记录。

## 专注计时如何接续

任务内容同步与正在运行的计时器接管是不同操作。另一台设备发现已有计时器时，会显示远端状态，不会自动开始重复计时。

要换设备继续同一次专注或休息，先在新设备查看远端计时器，再点击“接管并继续”。接管需要能够联系同步服务；旧设备在获知所有权已经变化后会停止继续拥有该计时器。离线设备无法立即获知其他设备的操作，因此不要在多台离线设备上同时把同一段时间当作同一次计时继续。

## 备份恢复和服务设置

电脑端写回同步数据时会创建并校验本机备份。在“同步状态与高级恢复”中，可以使用之前显示的备份编号恢复。备份恢复用于处理误操作，不是日常同步步骤；恢复内容属于本机历史版本，恢复后应核对数据及同步状态。

Android 的同步服务地址放在“高级：同步服务设置”中。通常无需修改。切换服务会退出当前账号，数据按服务和账号隔离，并不会自动搬迁到新服务。

## 大量旧数据首次导入的现有限制

日常上传已限制为小批次，会逐批确认和继续处理；这不等于首次导入支持任意大的快照。

当前电脑首次导入预览接口要求：本机快照不超过 **5,000 条内部记录**，记录数组序列化后的 UTF-8 大小不超过 **900,000 字节**（约 879 KiB）；预览所读取的账号快照也不能超过 5,000 条。单条记录的 payload 上限为 **256 KiB**。图片、图片分片和其他内部记录都需要计入相应限制，不能只按任务数判断。

超出限制时，首次导入可能被拒绝。日常批次优化没有移除这一限制，也没有把首次预览改成无限分页导入。应保留完整本机数据和现有备份，记录错误提示，等待支持大快照的导入方案或联系维护者处理。不要通过删除内容、拆散原始记录或反复重建账号来绕过限制。

服务额度问题和修复依据见 [同步额度排查记录](sync-quota-audit.md)。
